# Walk test (day 3)

Goal: the iPhone plays each story once as you walk up to it, offline, with the screen locked.

## How the app is wired

```
CLLocationManager ──fix──▶ LocationTracker.onFix ──▶ WalkSession.handle
                                                        │
                                   ProximityEngine.update (accuracy ≤ 25 m,
                                   inside radius, 2 fixes in a row, once per stop)
                                                        │ stop
                                                        ▼
                                   AudioPlayer.enqueue ──▶ plays one story at a time
                                                        │ onStart
                                                        ▼
                                   WalkSession.playedIDs / currentStop ──▶ WalkView
```

The trigger runs in the location callback, not in the view, because SwiftUI doesn't update views while the phone is locked.

Code lives in `ios/WalkAndTalk/WalkAndTalk/`, one folder per kind of thing. Xcode picks up new files and folders on its own (synchronized folders), so adding a file needs no project changes.

| Folder | File | Job |
| --- | --- | --- |
| `App/` | `WalkAndTalkApp.swift` | Entry point; creates the `WalkSession` |
| `Models/` | `Tour.swift`, `Stop.swift` | Plain data decoded from `tour.json` |
| `Engine/` | `ProximityEngine.swift` | Pure Swift trigger logic, unit-tested |
| `Services/` | `TourLoader.swift` | Reads `<route>/tour.json` and audio URLs from the app bundle |
| | `LocationTracker.swift` | CLLocationManager: Always permission, background updates, best accuracy, 5 m filter |
| | `TriggerLog.swift` | Field-test CSV (`enter`, `trigger`, `closest` per stop) in Documents; exported via share sheet. See `docs/field-test.md` |
| | `AudioPlayer.swift` | `.playback` audio session for the whole walk, story queue, resumes after calls |
| `Stores/` | `WalkSession.swift` | Observable walk state; connects location → engine → audio |
| `Features/Walk/` | `WalkView.swift`, `WalkDebugPanel.swift` | Start/Stop, current stop, "X of N stops", story text; debug panel |

Tests mirror this in `ios/WalkAndTalk/WalkAndTalkTests/` (`Engine/`, `Services/`).

Each tour pack is a **folder reference** (blue folder in Xcode): `tours/mexicali` and `tours/mexicali2` are bundled, so regenerating a pack updates the app with no Xcode changes. The app plays the route named in `WalkSession(route:)`, currently `mexicali2`. A new route needs its own folder reference and that default changed.

## 1. Unit tests

Xcode: pick any iPhone simulator, then **Product > Test** (⌘U). Or from the terminal:

```bash
cd ios/WalkAndTalk
xcodebuild test -scheme WalkAndTalk -destination 'platform=iOS Simulator,name=iPhone 17'
```

(Any simulator name from `xcrun simctl list devices available` works.)

Expect 11 passing tests: 8 in `ProximityEngineTests`; 2 in `TourPackTests`, which check that both tours and all their audio files are inside the app, and that the app's default tour loads; and 1 in `TriggerLogTests`.

## 2. Simulated walk (GPX)

Two tracks are in `ios/WalkAndTalk/GPX/` (generated by `pipeline/make_gpx.py`):

- `mexicali2-quick.gpx`: 5 m/s, no waiting, about 6 minutes.
- `mexicali2-walk.gpx`: 1.4 m/s, stands at each stop while the story plays, about 23 minutes. Use it for the 20-minute stability check.

The `mexicali2` stops are far apart, so neither track reaches a stop while another story is still playing. The story queue is covered only by the logic, not by these simulations.

Steps:

1. Run the app on a simulator (⌘R). Allow location when asked.
2. Turn on **Debug info** and tap **Start walk**.
3. Xcode menu **Debug > Simulate Location > mexicali2-quick** (or the location arrow in the debug bar).
4. Watch: "X of N stops" counts up 1 to 5 in order, each story is heard once, and a story never starts while another is still talking.
5. Lock the simulator (⌘L) partway through: stories should keep playing.
6. Tap **Stop walk** mid-story: audio stops immediately, and the debug panel shows "not walking" (GPS is off).

## 3. On the iPhone, offline, locked

1. Run once from Xcode on the phone. Allow location; when iOS later asks "Always", allow it. The debug panel shows the permission state.
2. Turn on airplane mode. (GPS still works in airplane mode.)
3. Walk to about 100 m from the first stop, open the app, tap **Start walk**, and lock the phone.
4. Walk up to each stop. The story should start within a few steps of entering the 35 m radius. The blue location pill in the status bar means background tracking is on.
5. To check accuracy at a stop, unlock and open **Debug info**: distance should drop below 35 m, with GPS accuracy at 25 m or better.

Note: a walk starts fresh each time you tap **Start walk**, so every stop can play again.

## Regenerating the GPX after a new tour pack

```bash
python pipeline/make_gpx.py tours/mexicali2/tour.json
python pipeline/make_gpx.py tours/mexicali2/tour.json --speed 5 --no-wait --out ios/WalkAndTalk/GPX/mexicali2-quick.gpx
```

It warns if the straight line between two stops passes through a stop that comes later, which would make that stop play out of order.
